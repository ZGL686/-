# 工程 Agent 记忆系统

这是一个面向单项目编码 Agent 的低成本、可审计 Markdown 记忆系统。它把“发生过什么”和“现在应该相信什么”分开：日志保留历史，当前状态和决策提供快速上下文。

本模板基于 [LLM Wiki 模式](./llm-wiki.md)，但做了工程化收敛：不引入数据库、Embedding、网络服务或特定笔记软件插件。Markdown 文件可由 Codex、Obsidian、Git 和普通命令行工具共同使用。

## 核心原则

1. 少记录过程，多记录影响未来工作的结论。
2. 日志是历史审计，不是当前事实的唯一来源。
3. `当前状态/`、`决策/` 和 `知识/` 是 Agent 的长期记忆本体。
4. 未经确认的候选记忆不能进入当前有效状态。
5. 新结论替代旧结论，但旧结论只标记为废弃，不删除。
6. 原始代码和文档仍是事实来源，记忆文件只保存结论、关系和来源路径。

## 目录结构

```text
工程记忆构建/
├── README.md
├── AGENTS.md                 # 记忆维护协议
├── llm-wiki.md               # 理念参考
├── 当前状态/                  # 每次会话优先读取
├── 决策/                      # ADR 和架构选型
├── 知识/                      # 稳定的模块、流程、规范、运维知识
├── 日志/                      # 单次任务的追加式历史
├── 模板/                      # Agent 创建页面时使用
└── 工具/memory_lint.py        # 无第三方依赖的检查与索引工具
```

## 记忆层次

| 层 | 内容 | 写入策略 |
| --- | --- | --- |
| 当前状态 | 项目概览、架构、约束、待办、已知问题 | Agent 提议，用户确认后更新 |
| 决策 | 架构、技术选型和工程决策 | 必须确认，旧版本保留并标记替代 |
| 知识 | 稳定流程、模块说明、开发规范、运维手册 | 确认后沉淀 |
| 日志 | 本轮目标、操作、变更、验证、下一步 | 实质任务结束后自动记录 |

## 六类任务标签

日志只使用一个物理目录，类型写入 `kind` 字段：

| `kind` | 适用场景 |
| --- | --- |
| `feature` | 新功能、行为变化、重构 |
| `ui` | 纯界面、外观、样式调整 |
| `bug` | 异常诊断、恢复、修复 |
| `discussion` | 解释、比较、架构讨论、计划 |
| `test` | 测试、审查、检查、验收 |
| `maintenance` | 文档、配置、依赖、清理、迁移 |

## 快速开始

1. 将本目录复制到目标项目仓库内。
2. 将 [`AGENTS.md`](./AGENTS.md) 合并到项目根目录的 Agent 指令文件中，或明确要求 Agent 读取它。
3. 首先填写 [`当前状态/项目概览.md`](./当前状态/项目概览.md)、[`当前状态/系统架构.md`](./当前状态/系统架构.md) 和 [`当前状态/当前约束.md`](./当前状态/当前约束.md)。
4. 完成实质任务后，让 Agent 执行“记忆同步”。
5. 需要检查时执行：

   ```text
   python 工具/memory_lint.py check
   python 工具/memory_lint.py index
   ```

## 固定操作

- `记忆同步`：生成日志，提出待确认长期记忆并刷新索引。
- `记忆检索 <关键词>`：从 MOC、当前状态和相关知识开始检索。
- `记忆体检`：检查断链、缺字段、重复决策和孤儿页面。
- `记忆压缩`：将重复历史归纳到当前状态或知识页，不删除原始日志。

详细规则见 [`AGENTS.md`](./AGENTS.md)，页面格式见 [`模板/`](./模板/)。
