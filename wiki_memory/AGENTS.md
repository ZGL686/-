# AGENTS.md — 工程 Agent 记忆维护协议

本文件是记忆系统的 Schema 层。它约束 Agent 如何读取、写入、压缩和检查工程记忆。将本文件合并到目标项目根目录的 `AGENTS.md`，或在项目 Agent 指令中明确引用它。

## 记忆模型

- `当前状态/`：当前有效的项目事实，每个主题只能有一个明确的 active 版本。
- `决策/`：架构、技术选型和会影响后续工作的工程决策。
- `知识/`：稳定的模块说明、流程、规范和运维知识。
- `日志/`：一次实质任务的追加式历史记录，不承担当前状态的唯一来源。
- `AGENTS.md`：Agent 的程序性记忆，规定本协议。

原始代码、配置、文档和用户提供的资料是事实来源。不要复制原文，只在记忆中记录结论、关系和相对路径。

## 会话开始时的读取顺序

1. 读取本文件。
2. 读取 `当前状态/项目概览.md`、`当前状态/系统架构.md`、`当前状态/当前约束.md`、`当前状态/当前待办.md`。
3. 读取与当前任务相关的 `active` 决策。
4. 读取相关知识页。
5. 只有需要追溯时才读取最近 1–3 篇日志或更早历史。

目标是让启动记忆包保持在约 6,000 tokens 内。不要为了“完整”而默认读取全部日志。

## 任务类型

每篇日志只设置一个主要 `kind`：

| kind | 适用场景 |
| --- | --- |
| `feature` | 新功能、行为变化、重构 |
| `ui` | 纯界面、外观、样式 |
| `bug` | 异常诊断、恢复、修复 |
| `discussion` | 解释、比较、架构讨论、计划 |
| `test` | 测试、审查、检查、验收 |
| `maintenance` | 文档、配置、依赖、清理、迁移 |

混合任务按主要交付物归类；实现过程中的测试不单独归为 `test`。用户明确指定类型时优先采用用户指定类型。

## 记忆写入规则

### 工作日志

完成实质任务后自动执行“记忆同步”，生成 `日志/YYYY-MM-DD-任务标题.md`。同一天标题冲突时追加 `-02`、`-03` 等后缀。

应记录：目标、确认的决策、检查范围、文件变更、测试摘要、结果、遗留问题和下一步。

不应记录：完整聊天、私人消息、内部推理、隐藏上下文、密钥、令牌和大段命令输出。

日志封存后不改写；需要更正时新增一篇日志并链接原日志。

### 长期记忆

只有影响未来工作的内容才进入 `当前状态/`、`决策/` 或 `知识/`。

任务结束时，在日志的“待确认长期记忆”部分列出候选。用户集中确认后，才把候选提升为长期页面。未确认内容不得写入 `active` 页面。

每个长期结论必须包含来源链接，例如：

```yaml
source_logs:
  - "[[日志/2026-08-21-任务标题]]"
```

新确认事实替代旧事实时：

1. 更新当前 active 页面。
2. 将旧决策标记为 `superseded` 或 `deprecated`。
3. 在新页面或日志中填写 `supersedes`。
4. 不删除旧页面。

### 页面元数据

长期页面和日志都使用 YAML frontmatter：

```yaml
---
type: state | decision | knowledge | log | moc
status: active | proposed | deprecated | superseded | archived
kind: feature | ui | bug | discussion | test | maintenance | architecture | process | module | operations
importance: high | medium | low
updated: YYYY-MM-DD
topic: stable-topic-name
source_logs: []
supersedes: null
---
```

## MOC 与工具

- `日志/MOC_工作日志.md` 是唯一工作日志索引。
- 新增或修改日志后运行 `python 工具/memory_lint.py index` 更新索引。
- `python 工具/memory_lint.py check` 只检查，不擅自修复问题。
- Obsidian 链接使用 `[[路径|别名]]`；表格中的竖线写成 `\|`。
- 记忆路径使用 `/`，不写机器特定的绝对路径。

## 固定操作

- `记忆同步`：生成日志，提出长期记忆候选，必要时更新索引。
- `记忆检索 <关键词>`：先查 MOC 和当前状态，再按需查知识页与历史日志。
- `记忆体检`：执行 lint，报告断链、缺字段、重复 active 主题和孤儿页面。
- `记忆压缩`：把重复历史归纳到长期页面，不删除原始日志。

## 健康检查边界

Agent 可以报告问题并提出修复方案，但不能在未获授权时批量删除历史、覆盖 active 决策或改变原始来源。
