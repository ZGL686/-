# 工作日志说明

本目录是工程记忆的事件层，记录每次实质任务发生了什么。长期有效的事实、决策、架构和流程必须沉淀到 `当前状态/`、`决策/` 或 `知识/`。

## 文件命名

使用：`YYYY-MM-DD-任务标题.md`。同一天标题重复时追加 `-02`、`-03` 等后缀。

## 六类 `kind`

| kind | 用途 |
| --- | --- |
| `feature` | 新功能、行为变化、重构 |
| `ui` | 纯界面、外观、样式 |
| `bug` | 异常诊断、恢复、修复 |
| `discussion` | 解释、比较、架构讨论、计划 |
| `test` | 测试、审查、检查、验收 |
| `maintenance` | 文档、配置、依赖、清理、迁移 |

混合任务按照主要交付物选择一个 `kind`。实现过程中的测试不单独拆成 `test`。

## 日志要求

每篇日志必须包含：

- 目标与结果
- 已确认的决策
- 检查与操作范围
- 文件变更
- 测试与验证
- 问题、下一步
- 待确认长期记忆

只记录摘要、结论和相对路径，不复制完整聊天、内部推理、密钥、令牌或大段输出。

## 索引

日志索引由 `工具/memory_lint.py index` 生成，写入 [`MOC_工作日志.md`](./MOC_工作日志.md)。不要维护分类子 MOC。
